# 校服交付质量证据链

追踪校服上衣和裤子从生产、抽检到学校分发及退换的质量依据。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括校服生产企业、教育采购联合体、学校验收人员、市场监管人员。

资料所依据的领域事实如下：

- 执法案例涉及不合格学生服装套装
- 涉案上衣和裤子依据中小学生校服国家标准判定
- 企业已出厂销售二百套涉案服装
- 学生服装按套交付时上衣与裤子可能来自不同生产班次
- 只按整套数量验收会掩盖单个部件不符合国家标准的问题
- 成衣发给学生后再追查容易丢失部件与批次的对应关系

质量证据链依次串联九个环节：供应合同、款号、面辅料、生产批次、抽样封签、检验项目、到校验收、分发去向、退换处理。

拆套换码、补货、复检、实验室更正、学校间调剂和学生退回都必须保持部件来源与数量平衡；最终付款或索赔必须能追溯到采用的标准版本和检验原件。

资料同时约定访问边界：厂家只能维护本企业的交付资料，学校只能查看本校学生所需的处置，监管与采购人员发现不合格时可以精确冻结受影响部件并追踪通知完成情况。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、证据链、平衡操作、约束和访问边界，并拒绝契约之外的字段。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
