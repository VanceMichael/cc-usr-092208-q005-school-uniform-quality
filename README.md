# 校服交付质量证据链

追踪校服上衣和裤子从生产、抽检到学校分发及退换的质量依据。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括校服生产企业、教育采购联合体、学校验收人员、市场监管人员。

资料所依据的领域事实如下：

- 执法案例涉及不合格学生服装套装
- 涉案上衣和裤子依据中小学生校服国家标准判定
- 企业已出厂销售二百套涉案服装
- 同一套服装的上衣与裤子可能来自不同生产班次
- 只按整套数量验收会掩盖单个部件不符合标准的问题

## 证据链结构（版本 2）

共享资料把供应合同、款号、面辅料、生产批次、抽样封签、检验项目、到校验收、分发去向和退换处理九个环节串成事件链，每个事件登记类型、说明、引用和部件流转：

- **部件级追踪**：上衣与裤子分别记账，拆套换码、补货、学校间调剂、学生退回等操作必须保持每个部件在各持有方之间的数量平衡，任何一步使持有量为负即视为来源断裂。
- **批次与凭证引用**：批次登记挂接面辅料，检验与复检引用标准版本，实验室更正必须指向已存在的报告，冻结只能针对已登记批次。
- **结算可追溯**：结算索赔事件必须同时引用采用的标准版本（如 GB/T 31888-2015）与检验原件编号，保证从最终付款或索赔能追到判定依据。
- **按角色限定可见范围**：厂家只能维护本企业交付资料，学校看到本校学生所需处置，监管与采购人员可冻结受影响部件、追踪通知完成情况。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、约束、证据链环节、角色权限和事件不变量。运行项目自带测试即可检查这些基础资料能够稳定读取：

```sh
go test ./...
```

仓库不保存账号、密钥、连接串或真实身份信息。
